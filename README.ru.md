# ChannelTerm

> Это русскоязычная вводная страница. Источниками истины для поведения, параметров и совместимости
> являются английский [README](README.md), текущий исходный код и `channelterm --help`.

ChannelTerm позволяет человеку и ИИ совместно использовать одну аппаратную терминальную Session.
ИИ не заменяет ваш терминал: он может читать данные и управлять устройством, пока вы остаётесь
подключены, видите его действия, вводите команды вручную и при необходимости вмешиваетесь.

```text
                    Физическое последовательное устройство
                                      |
                               Serial Transport
                                (одно соединение)
                                      |
                                      v
                          ChannelTerm Session SER-1
                             /                 \
                            /                   \
                  Терминал человека         Клиент ИИ / MCP
                 channelterm attach       инструменты чтения/записи
```

ChannelTerm поддерживает последовательное соединение и SSH-оболочки с PTY в Windows, Linux и macOS. Встроенного ИИ нет: через MCP реальные терминальные Sessions доступны людям и внешним ИИ-клиентам.

## GDB пользовательского пространства через MCP

В нативной Linux клиент MCP может через инструменты `debug_start` / `debug_command` / `debug_events` / `debug_stop` занять свободную Bash Session, установить точки останова, выполнять программу по шагам, просматривать переменные/потоки/регистры и отсоединиться. Первая версия требует, чтобы ChannelTerm, GDB, gdbserver и ELF находились в одной среде Linux. Поддерживается один inferior в режиме all-stop; обычная запись возобновляется только после восстановления терминала и проверки оболочки уникальным маркером.

```text
debug_start -> break_insert -> continue -> debug_events -> next/step/finish -> debug_stop
```

[Рабочий процесс, вызовы MCP, безопасный attach и локальные тесты PTY](docs/getting-started/gdb-debugging.md).

Для независимо запущенного GDB инструменты `debug_bridge_*` открывают доступ к уже подготовленной последовательной Session через аутентифицированный TCP-мост. ChannelTerm не запускает GDB или gdbserver. GDB использует `channelterm rsp-client`; аутентифицированное соединение автоматически продлевает аренду даже без трафика RSP, но не дольше 24 часов. После разрыва соединения эксклюзивная аренда сохраняется до проверки восстановления shell/TTY. Явное закрытие моста также закрывает Session. [Рабочий процесс внешнего моста](docs/getting-started/gdb-debugging.md#external-gdb-over-a-prepared-serial-session) описывает Windows/WSL2 и раздельную проверку на PTY и реальной плате.

Внешний мост поддерживает любую плату разработки под Linux с совместимым gdbserver, работающим через подготовленное последовательное соединение, и GDB, соответствующим целевой системе. Мост не ограничивает модель платы или архитектуру целевого процессора; отладка bare-metal не входит в область поддержки.

## Передача файлов по SSH

Используйте SFTP для передачи файлов и управления ими либо классический SCP для совместимых POSIX-серверов:

```bash
channelterm sftp user@192.168.1.50 ls /tmp
channelterm sftp user@192.168.1.50 put ./firmware.bin /tmp/firmware.bin
channelterm sftp user@192.168.1.50 get /tmp/log.txt ./log.txt
channelterm scp user@192.168.1.50 put ./release /tmp/release --recursive
```

Команды используют ту же аутентификацию по ключу/паролю и проверку сервера, что и SSH, но отдельное
соединение, независимое от терминальных Sessions. Для замены файлов нужен `--overwrite`.
Правила копирования каталогов, отмена и ограничения описаны в
[руководстве по передаче файлов](docs/getting-started/file-transfer.md#sftp-and-scp-over-ssh).

Передача файлов через общие терминальные Sessions использует небольшой протокол оболочки Linux.
Отдельные SSH-соединения для файлов используют SFTP или классический SCP.

## Общая SSH-оболочка

Используйте авторизованный закрытый ключ или введите пароль по запросу. Для зашифрованного ключа запрашивается парольная фраза (ни она, ни пароль не сохраняются).
Для неизвестного сервера проверьте показанный отпечаток и введите `yes`, чтобы сохранить его открытый
ключ в `~/.ssh/known_hosts`; изменённые ключи отклоняются. Запросы требуют интерактивного терминала:

```bash
# Терминал 1: открыть оболочку, затем выполнить в ней uname -a.
channelterm ssh user@192.168.1.50

# Терминал 2: наблюдать и использовать ту же оболочку.
channelterm attach SSH-1
```

Оставьте первую команду работающей: при её завершении этот Host и его Sessions закрываются. Локальный порт по умолчанию должен быть свободен; для отдельного Host используйте `--listen` и показанный адрес attach. Пути ключей, проверка сервера, порты и текущие ограничения описаны в [руководстве SSH](docs/getting-started/ssh-terminal.md).

## Быстрый старт: одна команда, один терминал

Выведите обнаруженные последовательные устройства, сохранённые Profile и, если доступен HTTP Host
по умолчанию, его Sessions:

```bash
channelterm list
```

Host может быть не запущен. Если он недоступен, `list` сообщает, что MCP offline, но продолжает
показывать локальные устройства и Profile.

| Часто используемый параметр | Действие |
| --- | --- |
| `--kind device`, `profile` или `session` | Показать только выбранные типы; несколько значений разделяются запятыми. |
| `--transport serial` | Показать только результаты для последовательного транспорта. |
| `--no-mcp` | Не запрашивать MCP Host и показать только локальные источники. |
| `--long`, `-l` | Добавить в таблицу полные непрозрачные ID Sessions. |
| `--json` | Вывести структурированный JSON для скриптов. |
| `--endpoint URL` | Запросить Sessions у нестандартного HTTP Host. |

Полный контракт параметров приведён в [справочнике CLI](docs/reference/cli.md#list).

Если нативная цель, например `COM50`, уже известна, этот шаг можно пропустить.

Если к Session должен подключаться ИИ-клиент, один раз настройте поддерживаемый клиент перед
подключением:

```bash
channelterm init --mcp
```

Выберите HTTP или нажмите Enter, чтобы использовать HTTP по умолчанию. Конфигурация содержит
локальные учётные данные Bearer. Перезагрузите или перезапустите ИИ-клиент, если он не увидел
изменения сразу.

Затем выполните только команду для своей платформы:

```bash
# Windows
channelterm attach COM8 --baud 115200 --label board

# Linux
channelterm attach /dev/ttyUSB0 --baud 115200 --label board

# macOS
channelterm attach /dev/cu.usbserial-110 --baud 115200 --label board
```

Одна команда `attach` открывает последовательное устройство и подключает текущий терминал. Если на
стандартном endpoint ещё нет совместимого Host, команда автоматически запускает временный локальный
HTTP MCP Session Host. Типичный вывод при запуске:

```text
Shared Session created: SER-1 (0123456789abcdef0123456789abcdef)
[ChannelTerm] Temporary Session Host started; it and all shared Sessions stop when this attachment exits. Run 'channelterm mcp --transport http' separately for a persistent Host.
```

Для этого быстрого сценария не нужен отдельный терминал с MCP-сервером. Пока attachment открыт,
настроенный HTTP MCP-клиент может использовать `http://127.0.0.1:37099/mcp` и работать с той же
Session `SER-1`. Временный Host и все принадлежащие ему Sessions завершаются вместе с attachment,
который его создал. Используйте постоянный Host только тогда, когда Sessions должны продолжать
работать независимо от этого терминала.

`--label board` — необязательное отображаемое имя, а не идентификатор. Другим клиентам следует
использовать `SER-1` или полный непрозрачный ID Session.

### Частые сценарии

| Задача | Команда |
| --- | --- |
| Открыть общую последовательную Session и автоматически запустить временный Host | `channelterm attach COM8 --baud 115200` |
| Настроить поддерживаемый ИИ-клиент для общего HTTP Host | `channelterm init --mcp` |
| Оставить Host и Sessions работающими независимо от терминала | `channelterm mcp --transport http` |
| Вывести список или подключиться к существующей Session | `channelterm list --kind session`, затем `channelterm attach SER-1` |
| Открыть приватное последовательное соединение без MCP | `channelterm attach COM8 --private --baud 115200` |
| Наблюдать структурированные события Session | `channelterm events SER-1` |
| Открыть пошаговое меню передачи файлов в текущем общем attachment | Нажмите `Ctrl+]`, затем `f` |
| Отправить или получить данные через общую Session | `channelterm file send firmware.bin --session SER-1` или `channelterm file receive /tmp/log.txt ./log.txt --session SER-1` |

Постоянный Host — отдельный длительно работающий процесс. После сообщения
`MCP Streamable HTTP listening on http://127.0.0.1:37099/mcp` другие оболочки и настроенные
ИИ-клиенты могут создавать Sessions или подключаться к ним. Отсутствие последующего вывода —
нормальное поведение. Нажмите `Ctrl+C`, чтобы остановить Host и все его Sessions.

Во время подключения доступны следующие клавиши:

```text
Ctrl+C      Отправить 0x03 удалённому терминалу
Ctrl+] q    Выйти из этого CLI; принадлежащий ему временный Host также остановится
Ctrl+] ?    Показать локальную справку по escape-командам
Ctrl+] ]    Отправить удалённой стороне буквальный байт Ctrl+]
Ctrl+] t    Включить или выключить локальные метки времени приглашения shell
Ctrl+] f    Открыть локальное меню отправки/получения файлов
Ctrl+] Esc  Отменить локальный escape-режим
```

Чтобы подключить поддерживаемый ИИ-клиент к тому же Host, выполните `channelterm init --mcp`, выберите HTTP, затем предложите клиенту вывести список или управлять `SER-1`. Аутентификация и работа клиента описаны в разделе [MCP-сервер](docs/getting-started/mcp-server.md).

Чтобы получить переиспользуемые инструкции по workflow, установите встроенный
[Agent Skill `cterm-serial-debug`](docs/getting-started/mcp-server.md#install-the-bundled-agent-skill)
в клиенте с поддержкой Agent Skills. `channelterm init --mcp` настраивает MCP-клиенты,
но не устанавливает Skill.

Начиная с v0.2.0, в [Releases](https://github.com/akira-init1/ChannelTerm/releases) доступен архив
`channelterm_skills_VERSION.zip`. Распакуйте его и скопируйте весь каталог `cterm-serial-debug`
согласно инструкции по установке Skill по ссылке выше.

ИИ также может самостоятельно создать общую Session. Сначала один раз выполните
`channelterm init --mcp` и выберите HTTP, чтобы настроить клиент. Затем запустите постоянный Host на
переднем плане командой `channelterm mcp --transport http` и передайте ИИ точное имя
последовательного порта и параметры связи. ИИ может вывести список портов, вызвать
`terminal_open_serial` и сообщить созданную ссылку `SER-N`, чтобы человек подключился командой
`channelterm attach SER-N`. Сам запуск Host не открывает порт: решение `ask` по-прежнему требует
явного подтверждения. `auto` возвращает `connect`, но ИИ всё равно должен вызвать
`terminal_open_serial`; Host никогда не открывает порт автоматически. Обычно Host останавливают
сочетанием `Ctrl+C`; при этом закрываются принадлежащие ему Sessions.

## Общий терминал на практике

Подключённый CLI отображает команду агента как локальный блок активности `AI`. `terminal_exec` не добавляет эту команду в историю свободной оболочки Bash. Строки после блока остаются необработанным выводом терминала устройства; после освобождения кратковременной аренды команды человек снова может вводить данные:

```bash
root@board:~#

──────── AI ────────
[18:52:31] >> echo agent-check
────────────────────
agent-check
root@board:~# echo human-still-here
human-still-here
root@board:~#
```

Точный вывод команды зависит от подключённого устройства. Блок `AI` — локальное представление структурированных событий Session; он не вставляется ни в поток байтов устройства, ни в сохранённый терминальный вывод. Необработанные нажатия клавиш и интерактивные программы по-прежнему используют `terminal_write` и сохраняют обычное поведение истории устройства.

## Зачем нужен ChannelTerm?

В традиционном последовательном терминале физическое подключение получает человек:

```text
Human ---- terminal ---- Serial device
```

В последовательном инструменте только для ИИ подключение получает ИИ, а человек остаётся вне работающего терминала:

```text
AI ---- MCP / serial ---- Serial device

Human         (not attached)
```

ChannelTerm сохраняет одно физическое подключение в общей Session:

```text
                         +---- Human terminal
                         |
Serial device ---- Session
                         |
                         +---- AI / MCP client
```

При таком подходе действия ИИ во время отладки оборудования остаются видимыми, а человек продолжает участвовать. Совместная работа — не просто повторное открытие одного порта: каждый клиент читает сохранённый необработанный вывод через независимый курсор, а все записи проходят через одну Session.

## ИИ, файлы и локальное управление

Та же общая последовательная Session может передавать обычные файлы и каталоги без ИИ-клиента и без отдельно устанавливаемого на плату агента передачи. В активном общем `attach` нажмите `Ctrl+]`, затем `f`, чтобы открыть пошаговое меню отправки/получения. Для каталогов используются стандартный tar и подтверждаемые блоки данных, позволяющие удобно отменять передачу. Те же операции доступны через команды:

```bash
channelterm file send firmware.bin --session SER-1
channelterm file receive /tmp/log.txt ./log.txt --session SER-1
channelterm file send ./build/release /tmp/release --session SER-1
channelterm file receive /var/log/myapp ./myapp --session SER-1
```

Если команда не задаёт удалённый путь назначения, данные сохраняются в `/tmp/cterm/mcp-files/`; интерактивное меню использует `/tmp/cterm/user-files/`. ChannelTerm создаёт недостающую иерархию каталогов назначения и повторно использует её при следующих передачах. Linux shell использует штатные `mkdir`, `stty`, `dd`, `wc`, `sha256sum` и `sleep`, а для каталогов также `tar`. ChannelTerm передаёт блоки ограниченного размера, сообщает о ходе операции и выполняет сквозную проверку SHA-256 для байтов файлов и tar-потоков каталогов. При передаче каталогов используются временные архивы на целевой системе, поэтому отмена останавливает передачу после текущего блока, не требуя передать весь оставшийся каталог. Временная аренда передачи блокирует других писателей ChannelTerm до завершения команды. Пока аренда действует, `Ctrl+C` в любом поставляемом клиенте подключения открывает локальное подтверждение отмены с ответом «Нет» по умолчанию. В остальных случаях оно сохраняет обычное значение для удалённого терминала. Требования и ограничения описаны в [руководстве по передаче файлов](docs/getting-started/file-transfer.md).

Чтобы ИИ работал в той же Session, настройте его MCP-клиент на тот же endpoint Streamable HTTP:

```text
http://127.0.0.1:37099/mcp
```

ИИ может использовать MCP-инструменты Session, чтобы вывести список и читать `SER-1`, выполнить команду в свободной Bash через `terminal_exec` или явно отправить необработанные терминальные байты через `terminal_write`. См. [руководство MCP](docs/getting-started/mcp-server.md) и [справочник инструментов](docs/reference/mcp-tools.md). `channelterm init --mcp` устанавливает конфигурацию клиента, а `channelterm init --mcp-show` выводит её. Обе команды предлагают HTTP или stdio, по умолчанию используется HTTP. Выведенная HTTP-конфигурация содержит локальные учётные данные Bearer; её нельзя передавать другим или добавлять в коммит.

`Ctrl+]` включает локальный escape-режим, и ChannelTerm локально показывает доступные команды. `Ctrl+] f` запускает пошаговую отправку или получение файлов/каталогов в текущем подключении. Пути по умолчанию — `/tmp/cterm/user-files/<basename>` и `./<basename>`; суффиксы `_1`, `_2` позволяют избежать перезаписи. `Ctrl+] t` по умолчанию выключен и добавляет локальные метки времени `[HH:MM:SS]` только перед уверенно распознанными приглашениями оболочки. Он не меняет вывод общей Session или MCP.

HTTP Host требует Bearer token и по умолчанию слушает только loopback-адрес. Встроенные CLI-клиенты
автоматически читают token локального пользователя. Host также может
[слушать в доверенной локальной сети](docs/getting-started/mcp-server.md#listen-on-a-lan); удалённые
клиенты должны использовать доступный адрес Host и передавать тот же token в заголовке
`Authorization`. Не публикуйте endpoint в недоверенной сети без TLS и дополнительных средств
контроля сетевого доступа.

## Возможности

- Одно последовательное подключение, принадлежащее Host и используемое совместно человеком через CLI и клиентами MCP.
- Независимые курсоры вывода и активности: один читатель не потребляет данные другого.
- Отображение записей агента в подключённых терминалах без изменения необработанного вывода Session.
- Прямой ввод человеком, включая удалённый `Ctrl+C`, пока ИИ остаётся подключённым.
- Отключение клиента без закрытия Session, которую используют другие клиенты.
- Обнаружение последовательных устройств с нативными именами Windows, Linux и macOS, профили TOML и приватные прямые подключения, когда совместный доступ не нужен.
- MCP через stdio или Streamable HTTP; общий сценарий CLI использует HTTP Session Host.
- Отправка и получение файлов/каталогов через CLI блоками ограниченного размера поверх существующей последовательной Session, с проверкой SHA-256 и безопасной распаковкой каталогов в промежуточной области.

## Примеры работы

### Отладка встраиваемого Linux

Подключитесь к плате один раз. ИИ читает сохранённый журнал загрузки и выполняет целевую диагностику, пока инженер наблюдает тот же вывод устройства и отвечает в работающей оболочке.

### ИИ действует, человек наблюдает

В свободной оболочке Bash ИИ отправляет неинтерактивную команду через `terminal_exec`. Подключённый CLI один раз показывает её как блок активности `AI`, а затем — реальные байты, полученные от устройства. Команда и внутренняя подготовка не попадают в историю Bash.

### Человек вмешивается

Человек может вводить данные в общую Session или отправить `Ctrl+C` удалённому терминалу, затем продолжить наблюдение либо отключиться через `Ctrl+] q`. Кратковременная аренда `terminal_exec` временно блокирует человеческий ввод. Обычные необработанные записи сериализуются на уровне байтов без арбитража состояния оболочки, поэтому клиенты по-прежнему должны избегать конфликтующих последовательностей необработанных команд.

## Как это работает

```text
Human CLI ---------+
                   |
                   v
            Session Host / Manager
                   |
AI via MCP --------+--> Session --> Serial Transport <--> Device
                        |    |
                        |    `-- serialized writes
                        `------- retained raw output
```

Session Host владеет физическим портом и управляет временем жизни Session. Serial Transport открывает независимый от протокола Channel; Session владеет единственным читателем Channel, ограниченным хранением вывода и активности в памяти и сериализацией записей. Адаптеры CLI и MCP используют одно и то же поведение Core. Представление, например подсветка и блок активности `AI`, остаётся вне сохранённых терминальных данных.

Ссылки на общие Session, например `SER-1`, действительны только внутри процесса Host, которому они принадлежат. Остановка Host закрывает его Sessions; отключение одного клиента — нет.

## Установка

Скачайте из [Releases](https://github.com/akira-init1/ChannelTerm/releases) архив для вашей ОС и
архитектуры и проверьте его по `SHA256SUMS` того же выпуска. Распакуйте архив и из полученного
каталога выполните `.\channelterm.exe install` в Windows или `./channelterm install` в Linux/macOS.
Для готовых бинарных файлов установка Go не требуется.

Для сборки из исходного кода требуется Go 1.26 или новее. Используйте поддерживаемый выпуск с
актуальными исправлениями и выполняйте сборку из корня репозитория:

```bash
git clone https://github.com/akira-init1/ChannelTerm.git
cd ChannelTerm
go build ./cmd/channelterm
./channelterm install
```

`install` копирует запущенный бинарный файл в стандартный каталог программ текущего пользователя,
создаёт команды `channelterm` и `cterm`, добавляет каталог в пользовательский PATH только при
необходимости и создаёт отсутствующую минимальную конфигурацию. Если PATH изменился, откройте новый
терминал. `channelterm uninstall` удаляет принадлежащие установщику команды и изменение PATH, но
сохраняет пользовательские данные. `channelterm uninstall --purge` требует явного подтверждения
перед удалением конфигурации, состояния устройств и локальных HTTP-учётных данных.

Стандартные расположения; после запуска установщик также выводит фактические пути:

| Платформа | Каталог команд | Состояние установки | Конфигурация по умолчанию |
| --- | --- | --- | --- |
| Windows | `%LOCALAPPDATA%\Programs\ChannelTerm\bin` | `%LOCALAPPDATA%\ChannelTerm\install.json` | `%APPDATA%\channelterm\config.toml` |
| Linux | `~/.local/bin` | `$XDG_STATE_HOME/channelterm/install.json` или `~/.local/state/channelterm/install.json` | `$XDG_CONFIG_HOME/channelterm/config.toml` или `~/.config/channelterm/config.toml` |
| macOS | `~/.local/bin` | `~/Library/Application Support/channelterm/install.json` | `~/Library/Application Support/channelterm/config.toml` |

Поддерживаемые настольные цели: Windows, Linux и macOS на amd64/arm64. Подробнее:
[сборка и установка из исходного кода](docs/getting-started/build.md), полный контракт
[`install` / `uninstall`](docs/reference/cli.md#install-and-uninstall),
[расположения конфигурации](docs/reference/configuration.md) и
[сборка и тестирование](docs/development/building-and-testing.md).

## Конфигурация

ChannelTerm хранит локальные файлы в пользовательском каталоге конфигурации платформы:

| Платформа | Каталог по умолчанию |
| --- | --- |
| Windows | `%AppData%\channelterm\` |
| Linux | `$XDG_CONFIG_HOME/channelterm/` или `~/.config/channelterm/`, если переменная не задана |
| macOS | `~/Library/Application Support/channelterm/` |

`config.toml` содержит управляемые пользователем последовательные профили и политику подключения.
`state.json` — состояние идентификации устройств, которым управляет ChannelTerm. `http-auth-token` —
секрет для аутентификации HTTP MCP-клиентов; не публикуйте его и не добавляйте в коммиты.

```powershell
# Сохранить и повторно использовать последовательный профиль.
channelterm serial --port COM8 --baud 115200 --save board
channelterm serial --profile board

# Использовать другой config.toml для этой операции.
channelterm serial --config ./channelterm.toml --profile board
```

Часто используемые параметры: `--profile`, `--save`, `--config`, `--port` и `--baud`. MCP Host также
поддерживает `--connection-policy ask|auto|deny`. Параметр `--config` меняет только выбранный
`config.toml`, но не стандартные `state.json` и `http-auth-token`. См. руководство по
[последовательным профилям](docs/getting-started/serial-profiles.md) и
[справочник по конфигурации](docs/reference/configuration.md).

## Планы развития

Последовательные подключения и SSH PTY shell реализованы как Transports; также доступны отдельные файловые клиенты SFTP и традиционного SCP. Произвольный SSH exec, Telnet и более строгая координация нескольких писателей остаются направлениями развития, а не реализованными возможностями или обещаниями выпуска.

Сейчас ChannelTerm не реализует JTAG/OpenOCD, виртуальные последовательные устройства, встроенный ИИ или оркестрацию нескольких агентов.
